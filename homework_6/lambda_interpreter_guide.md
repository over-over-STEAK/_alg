# Lambda Calculus 解譯器：中文說明與驗證

對應程式：`lambda_ready.py`  
實作語言：Python，使用標準函式庫  
表示方式：有名稱（Named）  
化簡策略：正規序（Normal order，最左最外優先）

## 一、作業目標

製作一個能讀取 Lambda Calculus 運算式的解譯器，提供一些 Lambda 程式作為輸入，並顯示完整計算過程。本版本會顯示初始運算式、每一步 α 改名或 β 化簡、化簡後的完整運算式，以及最後的停止狀態。

## 二、什麼是 Lambda 解譯器？

Lambda 解譯器就是讀取 Lambda Calculus 文字，按照規則一步一步代入、化簡，最後顯示結果的程式。

例如輸入：

```text
(\x.x) a
```

程式會理解這是「將 a 傳入一個接收 x、回傳 x 的函數」，因此結果為 a。

本程式會解析文字並自行執行化簡，不是直接把輸入當成 Python 程式執行。

## 三、三種基本結構

| 結構 | 範例 | 說明 |
| --- | --- | --- |
| 變數 | `x`、`a` | 運算式中的名稱 |
| 函數抽象 | `λx.x` | 定義一個接收 x、回傳 x 的函數 |
| 函數套用 | `(λx.x) a` | 將 a 傳入函數 |

程式接受 `λ` 或反斜線 `\` 表示函數抽象。終端機輸入時可以使用容易打出的反斜線：

```text
λx.x
\x.x
```

兩者意思相同。程式的輸出使用反斜線。

在 `λx.x` 中，λ 表示開始定義函數，第一個 x 是參數，句點分隔參數與函數本體，最後的 x 是本體。概念類似以下 Python 函數：

```python
def identity(x):
    return x
```

套用向左結合：`f x y` 等同 `(f x) y`。函數本體盡量向右延伸：`\x.x y` 等同 `\x.(x y)`。多參數簡寫 `\x y.x` 會解析成 `\x.\y.x`。作為引數的函數要加括號，例如 `f (\x.x)`。

## 四、β 化簡：將引數代入函數本體

β 化簡（beta reduction）的規則為：

```text
(λx.M) N → M[x := N]
```

意思是將 M 中 x 的自由出現替換成 N。

### 範例 1：恆等函數

```text
(\x.x) a
→ a
```

函數接收 x，回傳 x；傳入 a 後，將本體中的 x 換成 a。

### 範例 2：選擇第一個參數

```text
(\x.\y.x) a b
→ (\y.a) b
→ a
```

第一步以 a 代入 x。第二步將 b 傳給 y，但本體沒有使用 y，因此結果仍是 a。

## 五、自由變數、綁定變數與遮蔽

在 `λx.x y` 中，x 被 λx 綁定，y 沒有被這個項中的 λ 綁定，所以 y 是自由變數。

自由變數的計算規則：

```text
FV(x) = {x}
FV(λx.M) = FV(M) − {x}
FV(M N) = FV(M) ∪ FV(N)
```

同名的內層參數會遮蔽外層參數。例如：

```text
(\x.\x.x) a
→ \x.x
```

最裡面的 x 屬於內層 λx，不能被外層傳入的 a 替換。

## 六、α 改名：避免變數捕獲

考慮以下輸入：

```text
(\x.\y.x) y
```

如果直接將 x 換成 y，得到 `\y.y`，原本傳入的自由變數 y 就會被內層 λy 綁定，改變原本的意義。這稱為「變數捕獲」。

正確做法是先改名，再代入：

```text
(\x.\y.x) y
→ (\x.\y_1.x) y     alpha：內層 y 改成 y_1
→ \y_1.y            beta：將 y 代入 x
```

最後的函數接收 y_1，但回傳外面的 y。α 改名不改變函數意義，只是換掉綁定變數的名字。

程式會檢查已使用的名稱，必要時使用 y_1、y_2 等未衝突名稱。每次必要的 α 改名會單獨顯示，並與 β 次數分開統計。

## 七、程式如何處理輸入？

| 程式部分 | 工作 |
| --- | --- |
| `Parser`、`parse()` | 辨識符號、檢查語法，建立語法樹 |
| `Var(name)` | 表示變數 |
| `Lam(param, body)` | 表示函數的參數與本體 |
| `App(func, arg)` | 表示函數套用 |
| `free()` | 計算自由變數 |
| `names()` | 收集自由與綁定名稱 |
| `prepare_alpha()` | 每次進行一個必要的 α 改名 |
| `replace_free()` | 替換指定變數的自由出現 |
| `step()` | 依正規序執行一次 α 或 β 步驟 |
| `has_redex()` | 檢查是否還有可進行 β 化簡的子式 |
| `evaluate()` | 重複化簡並輸出完整過程 |
| `show()` | 把語法樹轉回可閱讀的文字 |

本版本以 `collections.namedtuple` 定義 Var、Lam、App。

例如 `(\x.x) a` 解析後的結構為：

```python
App(
    Lam("x", Var("x")),
    Var("a")
)
```

`replace_free()` 是內部代換函式。正式 β 代入前，必須先透過 `prepare_alpha()` 排除捕獲風險，不能將它單獨當成通用的安全代換函式。

## 八、化簡順序與停止條件

本版本使用正規序：優先化簡最左、最外層的可歸約式，並會進入 λ 本體，求完整 β 正規形。

例如：

```text
(\x.a) ((\z.z z) (\z.z z))
→ a
```

左邊函數沒有使用 x，因此可以直接得到 a，不必先計算不會停止的引數。

| 輸出 | 意義 |
| --- | --- |
| `NORMAL FORM` | 已沒有可以進行 β 化簡的部分 |
| `STEP LIMIT` | 達到步數上限，計算尚未完成 |
| `alpha` | α 改名的次數 |
| `beta` | β 化簡的次數 |
| `root.func`、`root.arg`、`root.body` | 化簡發生在語法樹的哪個位置 |

經典的 Omega 運算式是：

```text
(\x.x x) (\x.x x)
```

每次 β 化簡都回到相同的式子，因此沒有正規形。不能因為化簡前後文字相同就判斷已經完成。

對一般輸入而言，達上限只代表目前尚未完成，不一定表示永遠不會停止。Normal order 在正規形存在時有理論上的到達保證，實際程式仍受步數與電腦資源限制。

## 九、Church 數字與布林值

純 Lambda Calculus 沒有內建數字或布林值，但可以用函數表示。

TRUE 選擇第一個參數，FALSE 選擇第二個參數：

```text
TRUE  的表示法：\t.\f.t
FALSE 的表示法：\t.\f.f
```

Church 數字 n 表示將函數 f 套用 n 次：

```text
0：\f.\x.x
1：\f.\x.f x
2：\f.\x.f (f x)
3：\f.\x.f (f (f x))
```

程式中的加法範例為 1 + 2，結果是套用 f 三次的函數；乘法範例為 2 × 2，結果是套用 f 四次的函數。程式顯示純 Lambda 結果，不自動將結果轉成十進位數字。

**此版本沒有巨集或數字字面值功能，不能直接輸入 `ADD 2 3`。** TRUE、FALSE 等名稱在本節只是方便說明的標籤；內建範例使用的是展開後的完整 Lambda 運算式。

## 十、啟動與操作方式

將 `lambda_ready.py` 放進作業資料夾，在 VS Code 的終端機切換到該資料夾。

### 1. 執行內建驗證

```bash
py lambda_ready.py --self-test
```

通過時最後會顯示：

```text
Ran 11 tests
OK
ALL TESTS PASSED
```

實際輸出另有 Python 版本、測試名稱與耗時。

### 2. 顯示全部範例

```bash
py lambda_ready.py --examples
```

### 3. 計算指定運算式

```bash
py lambda_ready.py --expr "(\x.x) a"
```

輸出範例：

```text
0. ((\x. x) a)
1. [beta] root: replace free x with a in x
   => a
NORMAL FORM
alpha: 0, beta: 1
```

### 4. 測試變數捕獲

```bash
py lambda_ready.py --expr "(\x.\y.x) y"
```

應先看到 alpha 改名，再看到 beta 代入，結果為 `(\y_1. y)`。

### 5. 自行連續輸入

```bash
py lambda_ready.py --repl
```

在 `lambda>` 後輸入運算式；輸入 `quit` 離開。不加參數執行程式，也可以從選單選擇範例或互動模式。

### 6. 設定單次計算的步數上限

```bash
py lambda_ready.py --expr "(\x.x x) (\x.x x)" --max-steps 8
```

上限包含 α 與 β 步驟。`--max-steps` 在此版本用於 `--expr` 模式；內建範例與互動模式使用程式設定的上限，Omega 範例固定示範 8 步。

### 7. 保存驗證與範例結果

```bash
py lambda_ready.py --self-test > verification.txt
py lambda_ready.py --examples > results.txt
```

這會在目前資料夾產生文字檔，可用於檢查與繳交。

## 十一、驗證內容與限制

本次 AI 執行環境已實際使用 Python 3.9.25 執行，11 項測試全部通過。其中範例測試另外逐一檢查 11 個 Lambda 輸入。也實際檢查選單、互動輸入、變數捕獲、步數截停與錯誤輸入的處理。

測試涵蓋範例結果、α 改名紀錄、新名稱衝突、巢狀遮蔽、向左結合、多參數簡寫、顯示後重新解析、錯誤語法、步數邊界、負數上限及 λ 符號輸入。

這些是 AI 執行環境的驗證結果，不表示使用者自己的 Windows 電腦已測試成功；可執行 `--self-test` 取得本機結果。

本版本限制如下：

- 採有名稱表示法，沒有 De Bruijn 模式或應用序選項。
- 不支援巨集、數字字面值、一般算術符號或 η 化簡。
- 運算式中的名稱使用英文字母、底線與數字，不能以數字開頭。
- 採遞迴方式處理語法樹，很深或快速膨脹的運算式可能超過資源限制。
- 步數上限不是時間或記憶體上限，也不是一般性的終止判定器。

## 十三、作業簡介

本專案使用 Python 實作有名稱的 Lambda Calculus 解譯器。程式先將輸入文字解析成語法樹，再以正規序執行 β 化簡。若代入可能造成變數捕獲，會先進行 α 改名。每個步驟都顯示完整運算式，直到到達正規形或步數上限，讓使用者看見函數套用與代換的計算過程。
