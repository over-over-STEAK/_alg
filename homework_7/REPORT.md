# 單字搜尋：動態規劃與 Boyer–Moore 比較

## 問題定義

給定長度 n 的文字 T 與長度 m 的模式 P，輸出所有滿足 T[s:s+m] = P 的位置 s。兩種方法均保留重疊匹配，大小寫敏感。以下複雜度以 m>0、單次碼位比較為常數時間分析，z 表示輸出位置數。

## 方法一：動態規劃（DP.py）

定義 dp[i] [j] 為 T 的前 i 個字元與 P 的前 j 個字元，結尾最長共同連續字串長度。

- 初始化 dp[0] [j] = dp[i] [0] = 0。
- 若 T[i-1] == P[j-1]，dp[i] [j] = dp[i-1] [j-1] + 1。
- 否則 dp[i] [j] = 0。
- 當 dp[i] [m] == m，整個模式已匹配，記錄 i-m。

相等時，新的連續匹配長度由前一個對角狀態延長；不等時連續關係中斷，必須歸零。逐列計算保證依賴狀態已完成。

例如 T=banana、P=ana，在 i=4 與 i=6 時 dp[i] [3]=3，所以答案是 [1,3]。

本題是判定與位置列舉，不是在求最佳決策。DP 表格可計算相鄰狀態；此版本刻意保留完整表格以利說明，不代表 DP 是精確字串搜尋的高效首選。時間 O(nm)，額外表格空間 O(nm)，結果空間 O(z)。可用滾動列將表格空間降為 O(m)，本作業沒有實作此優化。

## 方法二：Boyer–Moore（BM.py）

先建立壞字元最後出現位置表，以及強好後綴位移表。每次將模式對齊文字，從模式最右端往左比較。

1. 壞字元：失配位置是 j，文字字元為 c，候選位移是 j-last[c]，未出現時 last[c]=-1。
2. 好後綴：右端已匹配的後綴，可與模式中符合前置字元限制的另一個出現位置對齊；若無，嘗試與模式前綴對齊。
3. 失配時取 max(1, 壞字元位移, 好後綴位移)。
4. 完整匹配時記錄位置，依模式的邊界資訊移動，避免跳過重疊答案。

good_suffix_shifts 使用 border 記錄後綴邊界，先處理強好後綴，再填補可與模式前綴對齊的位移。完整匹配使用 shift[0]，在 j 失配時使用 shift[j+1]。

依作業分類，這是非 DP 方法：核心搜尋藉由失配規則跳過不可能的位置，不建立文字與模式的二維匹配表。預處理有陣列不代表它就是前述 DP 解法。

此版本沒有 Galil 優化，且列舉所有匹配。預處理 O(m) 時間與 O(m) 空間（字典操作以平均 O(1) 計）；搜尋保守最壞界 O(nm)，額外搜尋空間 O(m)，結果 O(z)。重複字元與大量重疊匹配可能重複比較長模式，不能宣稱此實作保證線性。某些有利的無匹配資料可大幅跳躍，但不應把有利情況當成所有資料的保證。

## 正確性驗證

使用獨立的暴力切片比對產生預期位置，而不是只檢查 BM 與 DP 彼此相等。

- 10 組明確案例：中文、Emoji、大小寫、換行、重疊、空文字、空模式與長模式。
- 窮舉二元字母表：文字長度 0–7、模式長度 0–4，共 255×31=7,905 組。
- 固定亂數種子：500 組混合字元案例。
- 共 8,415 組輸入，每組同時驗證 BM 與 DP。

本次 AI 執行環境實測全部通過。這是有限測試結果，不是對任意輸入的形式證明。

## 效能測試設計

benchmark.py 使用 1,000、5,000、10,000 字元，各有一般文字、大量重疊與無匹配三類資料。每組跑兩種方法，先與暴力答案比較，再各執行五次取中位數。

時間包含演算法自身的預處理與結果清單建立，不包含產生測試資料、正確性檢查、列印或讀檔。記憶體另一次執行，以 tracemalloc 測量 Python 配置峰值，不等於整個程序的作業系統記憶體。BM 與 DP 均每次重新預處理，沒有讓某一方重用資料。

本次環境的實際數據與平台資訊在 benchmark_result.txt；不能直接推廣到所有電腦、模式長度與文字分布。大量重疊案例也包含儲存大量答案的成本。本測試的模式長度只有 9 與 20，不能用它推論長模式的全部行為。
